# ADR-0006: Інфраструктура як код — Terraform (провіжинінг) і Ansible (конфігурація)

- **Статус:** Accepted
- **Дата:** 2026-11-27
- **Лабораторна:** №4

## Контекст

Сервер для LabRunner має створюватися й налаштовуватися відтворювано, без ручних дій у консолі й без дрейфу конфігурації між середовищами. Цільова хмара — публічний провайдер (Azure / GCP), але на момент лабораторної в команди немає доступної підписки: Azure for Students вимагає університетської пошти, а звичайні пробні акаунти — банківської картки.

## Рішення

1. **Розподіл відповідальності:**
   - **Terraform** — декларативний провіжинінг ресурсів (мережа, правила доступу, диски, VM) та передача даних далі: Terraform сам генерує `infra/ansible/inventory.ini`;
   - **Ansible** — конфігурація ОС всередині VM без агентів, по SSH: оновлення, захист (UFW, SSH без паролів, fail2ban), Docker Engine + Compose, каталоги застосунку. Плейбук ідемпотентний: повторний запуск дає `changed=0`.
   - Мінімальний first-boot (користувач + SSH-ключ) робить cloud-init.
2. **Дві цілі Terraform з однаковою структурою:**
   - `infra/terraform/kvm` — **застосовується**: KVM/QEMU через libvirt (провайдер `dmacvicar/libvirt` 0.8.3) у WSL2 на машині розробника — ізольована NAT-мережа `10.40.1.0/24`, пул дисків, base-образ Ubuntu 24.04 + copy-on-write диск VM, cloud-init, VM 2 vCPU / 4 ГБ;
   - `infra/terraform/azure` — **готова до застосування** конфігурація Azure (resource group, VNet/subnet, NSG, Public IP, NIC, Ubuntu 24.04 VM `Standard_B2als_v2`); перевіряється в CI (`terraform validate`), застосовується, щойно з'явиться підписка. Плейбук Ansible для обох цілей однаковий.
3. **Безпека мережі (найменші привілеї):** в Azure SSH дозволено лише з IP оператора, відкриті тільки 80/443, NSG прив'язано і до підмережі, і до NIC; у KVM VM доступна лише з хоста (NAT). На самій VM — UFW (deny incoming, allow 22/80/443) як другий рубіж захисту.
4. **Прийняті ризики (DevSecOps):** Trivy повідомляє AZU-0047 (80/443 відкриті з Інтернету) — це вимога публічного веб-сервісу, виняток задокументовано в коді (`#trivy:ignore:AZU-0047`); AZU-0076 (публічна IP на NIC, MEDIUM) — допустимо для навчального середовища без bastion-хоста.
5. **Стан Terraform** (`terraform.tfstate`) зберігається локально й ніколи не потрапляє в Git (`.gitignore`: `*.tfstate*`, `.terraform/`, `terraform.tfvars`). `.terraform.lock.hcl` комітиться — він фіксує версії та контрольні суми провайдерів. Для командної роботи цільове рішення — backend `azurerm` (Storage Account з блокуванням стану через lease).
6. **CI:** джоба *IaC validate* перевіряє `terraform fmt` / `validate` для обох цілей, `ansible-playbook --syntax-check` і `ansible-lint` (профіль `production`); Trivy сканує Terraform на помилки конфігурації.

## Наслідки

- Середовище створюється однією командою `terraform apply` і повністю видаляється `terraform destroy`; налаштування сервера повторюване та перевірене на ідемпотентність.
- Перехід на хмару не потребує змін в Ansible: змінюється лише каталог Terraform.
- KVM-ціль не має публічної IP-адреси, балансувальника та хмарних правил безпеки — ці частини перевіряються лише статично (validate, Trivy) у конфігурації Azure.
- Локальний стан Terraform не підходить для команди (немає блокування й спільного доступу) — при переході в хмару потрібен віддалений backend.
